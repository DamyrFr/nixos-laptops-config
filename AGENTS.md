# AGENTS.md

Repo-specific guidance for AI agents working in this NixOS flake config.
The README covers basics; this file captures only non-obvious gotchas.

## Verify / build

- Validate before committing: `nix flake check` (or `make check`).
- Build a host: `sudo nixos-rebuild switch --flake ~/nixos-config#<host>`.
  Host attributes are `ghost`, `lapwar`, `dust`.
- On-host rebuild alias: `nixupgrade` (uses current `hostname`).
- Flakes only see `git add`-ed files. New files must be staged before they
  exist to the build.
- `Makefile` target `nixos-build-waays` references `#waays`, which is NOT a
  flake attribute (the attribute is `lapwar`). Target is stale; use the
  `nixos-rebuild` command directly or `nixupgrade`.

## Host / module layout gotchas

- `lapwar` host is built from `hosts/waays/` (directory name and flake
  attribute differ). Do not assume `hosts/lapwar/`.
- `modules/pro/` is imported only by `lapwar` (see `flake.nix`).
- `modules/home/home.nix` is NOT imported by `modules/home/default.nix`.
  It is imported per-host in `flake.nix` via
  `home-manager.users.<username> = import ./modules/home/home.nix;`.
- `modules/desktop/hyprland.nix` exists but is not enabled (GNOME only;
  hyprland import is commented out in `modules/home/home.nix`).
- `dust` and `lapwar` use `disko` for partitioning (`hosts/*/disko.nix`).

## Git identity (do not break)

Git identity is selected per-remote via `includeIf "hasconfig:remote.*.url:"`:
- `github.com` remotes -> DamyR `<thomas@anvir.fr>`
- `git.waays.fr` remotes -> tw `<tg@waays.fr>`

Default identity is DamyR on `ghost`/`dust`, overridden to tw on `lapwar`
via `modules/pro/git.nix` (`lib.mkForce` on `programs.git.config.include.path`).

CRITICAL: the default identity MUST be set via `[include].path`, never an
inline `[user]` section. The NixOS `programs.git` module renders sections
alphabetically, so an inline `[user]` would always sort AFTER `[includeIf]`
blocks and clobber the per-remote identities (Git is last-value-wins).
Long comment in `modules/core/packages.nix` explains why.

## Runtime-managed files (do not hand-edit)

- `~/.zshrc`, `~/.zshenv`, `~/.zprofile`, `~/.config/nvim/init.lua` are
  generated by home-manager / NixOS. Edit the `.nix` source and rebuild.
- Neovim config is cloned at first login by the `neovim-config-sync`
  systemd user service from `github.com/DamyrFr/neovim-config`.
  `modules/home/neovim.nix` only injects `extraLuaConfig` (`require`
  calls); editing local `init.lua` won't persist across syncs.
- `/etc/zshrc`, `/etc/zshenv`, `/etc/zprofile`, `/etc/environment` are
  symlinks into `/nix/store`. Never edit directly.
- `.claude/` and `result` are gitignored. Agent/skill config under
  `.claude/` is installed by `modules/home/agent.nix` (via `builtins.fetchurl`
  with pinned `sha256`). Update a pinned skill by changing the sha and
  rebuilding.

## Known system-level gotchas

- `EDITOR` defaults to `nano` at the system level (NixOS default in
  `nixos/modules/programs/environment.nix`). `home-manager` sets
  `EDITOR=nvim` only in zsh session vars (`~/.zshenv`, `~/.zprofile`), so
  non-interactive / systemd / non-zsh contexts still see `nano`
  (`systemctl --user show-environment` -> `EDITOR=nano`). To fix at system
  scope, set `environment.variables.EDITOR = "nvim";` in a `modules/core/`
  module.
- Sudo is passwordless for the `wheel` group.
- `system.autoUpgrade` runs daily with `--update-input nixpkgs
  --commit-lock-file` (no reboot). The lock file gets auto-committed.
- `boot.loader.systemd-boot.configurationLimit = 5` (only 5 boot entries).
- `nix.gc` weekly, deletes generations older than 7 days.

## Toolchain notes

- `modules/home/k9s.nix` overrides `python311Packages.os-service-types`
  to add `typing-extensions` as a build dep. Don't remove without verifying
  k9s still builds.
- `modules/home/agent.nix` installs `claude-code`, `opencode`, `rtk` and
  fetches external skill files with pinned `sha256`.
